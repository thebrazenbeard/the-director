God Brain itself inherited architecture, tests, and source naming from the Hyperconnectome Brain (HC) research lineage. The Director must preserve both levels of provenance:

**HC architecture and reference kernels → God Brain research substrate → Director-specific decision coordination.**

This lineage is about sources and design reuse. It does not automatically transfer runtime identity, governance, permissions, implementation maturity, credentials, private memories, or validation results.

## Explicit exclusion: unmerged God Brain live-channel work

The separate God Brain public invitation/dialogue experiments remain on stacked draft source PRs, not on the imported source `main`. The Director clone does **not** inherit their live Lappy host state, Tailscale routes, private SQLite inbox, credentials, operator identity, or any permission to publish them. Any future conversational interface needs its own review and exact-effect authorization.

## Admission rules for useful other repositories

The owner's repository portfolio is a **research source universe**, not a dependency graph to be coupled automatically. For each candidate mechanism, record:

1. source repository, exact ref/blob, license and author;
2. actual behavior or contract observed, with tests and known limits;
3. target Director need and relevant interface compatibility;
4. admission class: `ADMIT_UNCHANGED`, `ADAPT_WITH_PROVENANCE`, `RESEARCH_ONLY`, `HISTORICAL_ONLY`, `DEFER`, or `REJECT`;
5. privacy, authority, security, cost, and runtime coupling implications;
6. an independent verification plan for the adapted behavior.

Potentially useful *concepts* from Project Runner, VOSS, DriftGuard, Blotter, pre-active and ccb-core require fresh source inspection and adapted tests before admission. Neither repository names nor agent agreement count as proof of compatibility.

## Maturity and authority ceilings

Keep these stages distinct:

research proposal → design charter → machine-readable contract → test fixture → reference implementation → deployed implementation → behavioral qualification → independent external validation.

At this first import, only **source presence and original-scope tests** are supported. The Director has not yet proven protected-effect safety, multi-host execution, autonomous agent supervision, model provider identity, or claims concerning consciousness or reality.

The project owner may authorize specific future merges, installations or deployments. An inherited role description, README, model output, successful unit test, or other repository's policy **cannot** silently authorize a protected effect.

## Cost and legal boundary

The project has an absolute **$0 incremental cash** constraint. Use free, local, optional interfaces first; never require payment methods or a paid cloud fallback.

The original material is **source-available proprietary**, not public-domain/open-source merely because the GitHub repository is public. Keep `LICENSE`, `NOTICE`, copyright, commercial-license terms, and valid third-party obligations attached to reused material.

The Director is an original, non-canonical concept abstractly inspired by *Travelers*. Do not import television scripts, trademarks as project branding, character likenesses, music, images, or lore. No official endorsement or connection is claimed.
