# The Director v0.7 — isolated broker, bounded reasoning, Lappy qualification

Status: implementation plan, not a host authorization or deployment claim.

## Global Constraints

- Baseline is the merged v0.6 `main` commit `cc051c0d8961aeaf705ad8092e5f42ae9836b978`.
- Zero billable infrastructure and no Vercel, cloud registration, credit card, new paid dependency, listener on the public Internet, or automatic host installation.
- No false security equivalence: subprocesses, Python sandboxes, shared-route HMAC, caller-supplied worker IDs, unit mocks, same-UID Unix sockets, and successful CI do **not** qualify hostile-worker OS isolation on Lappy.
- A worker must not be able to read broker keys/databases or issue its own approvals, and untrusted payload data must never become arbitrary Python/shell/file/network execution. If real OS principal and protected IPC cannot be proved, execution remains fail-closed.
- Preserve existing v0.4/v0.5/v0.6 coordinator, mailbox, signed-message, receipts, agent-state recovery and read-only decision-cycle interfaces and tests. No hidden migration of existing SQLite files.
- Every broker operation has bounded input, explicit peer identity, policy epoch/fencing, durable replay identity and recovery semantics. ACK is not proof of effect. A cancellation must deny future broker-issued capabilities, not pretend to delete an already-returned data copy.
- Local evidence may be acquired from explicit operator-registered, finite, read-only sources; their contents are assertions, not independent truth or permission. No automatic success confirmation or dependency completion from untrusted source text.
- Resource budgets and stop/pause are binding at bounded decision/admission checkpoints. The loop must terminate on no progress, contest, exhaustion, invalid input, or permission failure. Until a preemptible isolated host worker exists, a POSIX regular-file synchronous read can stall inside the OS; wall-clock deadlines are explicitly **cooperative**, not a hard real-time guarantee. A built-in local read must be separately reported as an actual local read, not `NOT_EXECUTED`.
- Source and synthetic tests do not constitute a real Lappy Windows isolation, service, sleep/reboot, ACL, process-tree, or uptime probe. A host-reported PASS must require host-owned evidence; unsupported/unproven features stay blockers.
- Repo remains source-visible proprietary; do not copy nonlicensed code from sibling repos. Documentation may link to source-inspired patterns with attribution.
- Each task requires focused tests and independent hostile spec/security review; full test suite, cross-platform CI and exact-commit review required before merge. Any blocker leaves PR draft; do not install a service without actual qualification.

## Task 1 — Broker-owned policy and credential-bound IPC

Implement a narrowly scoped broker core in new `runtime/director/` modules (do not rewrite the legacy mailbox). Use one broker-owned SQLite transaction for registered identities, immutable command payload/nonce/digest, per-worker queue, replay/receipt, cancellation or revocation policy epoch and statuses. `POLL`, `ACK_RECEIPT`, `REPORT_CLAIM`, `GET_RECEIPT` only; command admission and policy changes are *trusted broker/operator calls*, never available through worker IPC. No generic process launch, file read, arbitrary path, code import or effect authority.

Provide Linux AF_UNIX connector with kernel `SO_PEERCRED` to derive UID before route selection. Configuration binds worker ID to pre-provisioned *distinct* UID; same broker UID is rejected as a hostile-worker deployment. Store and socket parent permissions must be externally protected. Reject malformed/oversized/invalid versions, alternate worker labels, unknown IDs, replay conflicts, stale epoch, unauthorized ACK and wrong peer UID; fail closed on Windows rather than dropping to caller-provided identity. Keep the server opt-in and foreground-only, bounded per connection and no import-time listener. Do not assert same-UID tests prove separate-UID security.

Add `tests/test_director_v07_broker.py` covering durable crash/restart recovery, duplicate/replayed message conflicts, revocation before admission and before claim, wrong identity, bounded framing, malformed and spoofed requests, and fail-closed platform behavior. Any claimed `HOST_QUALIFIED` state requires actual distinct-principal integration evidence that we do not yet possess.

## Task 2 — Close one bounded local evidence/reasoning iteration

Add an opt-in `runtime/director/local_engine.py` composition path, separate from unchanged legacy `coordinator.tick()`. Consume `DirectorCoordinator.assess_decision_cycle()` and actual graph readiness, choose supported discriminating probe or prerequisite where allowed, read only an explicitly registered bounded local JSON source via a *fixed* built-in adapter (no arbitrary callables/paths from model output), record receipt/source digest and admit a clearly `UNVERIFIED_SOURCE_CONTENT` observation through existing bounded APIs. The six-field world event schema is immutable: store source authenticity/provenance labels and immutable content hash in a separate durable receipt bound to the event, not invented fields. Re-evaluate after actual read, expose before/after revision/digest and stop reason. Do not automatically attest success, mark graph completion or authorize host effects. Recheck pause, stop and quarantine before local reads **and atomically with observation admission**; existing `coordinator.observe()` alone does not reject pause/stop. Stop on repeated unchanged source, conflict or no progress. Bound total read bytes and steps, and enforce elapsed-time budgets cooperatively at checkpoints, not as hard syscall deadlines. Never classify one untrusted JSON source as independently corroborated, and never make a contradicted rival disappear as if it had been disproven by verified reality.

Tests in `tests/test_director_v07_local_engine.py` must demonstrate actual file-read->observation->hypothesis update, distinct-metric prerequisite handling or explicit dependency block, prompt/authorization claims ignored, replay idempotence, symlink/oversize/nonfinite refusal, pause/stop/quarantine blocking reads, no unintended ACK/execute and deterministic bounded termination.

Time-bound interpretation: `max_seconds` bounds cooperative checkpoints and elapsed-budget decisions; it cannot forcibly terminate a stalled synchronous filesystem syscall. This source milestone must advertise that limitation. A hard execution deadline belongs to the future independently isolated worker-host qualification, not the data-only source acceptance gate.

Hostile-review clarifications for Task 2:

- Register a fixed metric/source/adapter mapping outside all source JSON; the adapter assigns event IDs and provenance. Use a separate durable receipt with registered-source identity, acquisition digest, raw bytes hash, selected value, adapter version, unverified classification and revision. Do not forge new fields in `WorldState`. Reserved local acquisition IDs must not be preempted by ordinary `observe()` input; a preexisting collision must cause a bounded explicit denial, never a perpetual uncaught error.
- Do not hold a SQLite write transaction around slow filesystem I/O. Fence assessment and control state before reading, and revalidate the controls plus assessment digest atomically in the final admission transaction. An operation admitted before a later STOP may already have read data; report that truthfully. Stale reads can retain a record without world-state admission.
- On POSIX, protect each component of a registered source path with no-follow descriptor-relative opening (or fail closed if unsupported), then `fstat` a regular opened descriptor and read/hash exactly those bytes. Handle oversized, special files, changing contents, duplicate JSON keys, nonfinite and excessively nested JSON. Windows reparse safety requires separate qualification; do not silently claim it.
- Durable idempotence must not depend on changing world revision or arbitrary event ID. Receipt and observation must be atomically bound or recoverably reconciled. Repeated unchanged metric values, irrelevant JSON changes, conflicting histories and a single untrusted source selecting one hypothesis must not count as verified convergence or success.
- Do not call legacy `tick()`, send/ACK a mailbox message, confirm observations or mark graph nodes complete. A ready prerequisite may be *measured* but must stay completion-blocked until the established operator-review path is satisfied.

## Task 3 — Qualify unattended Lappy honestly

Extend `unattended_qualification.py` with a read-only, bounded host-evidence schema and a foreground `scripts/director-v07-qualify-lappy.ps1` (or simpler cross-platform source probe if PowerShell unavailable). The source probe may inspect *current* Windows OS/process/control status and produce a reproducible report; it cannot self-attest ACL/process separation based on flags supplied by the caller or manufacture a passing host grade. Add explicit probes/checklist for distinct SIDs, protected broker keys/DB, peer-binding, job/tree cleanup, restart caps, stop controls, one-instance lock, sleep/reboot and revocation crash matrix. Reject forged all-PASS booleans and copied/stale/wrong-host/wrong-boot/wrong-commit untrusted reports as authorization. Host evidence needs a separately defined collection principal, tamper-resistant custody, binary/config and boot binding, freshness and independent verification before it can ever support qualification; these features are not established here. No input or evidence snapshot is an authority token. Where safely testable without an installed broker, report `NOT_TESTED`/`UNQUALIFIED_HOST`.

Use Executor only for read-only Lappy discovery until there is independently tested broker/worker principal separation; no remote service installation, scheduler change, host policy change, password prompt, ACL alteration or listener. Add `tests/test_director_v07_lappy_qualification.py` and clear `docs/director/V07_HOST_EVIDENCE.md` distinguishing TEST, REAL_HOST_PROBE and UNPROVEN. Include exact commands for a future approved host test, not invented output. New Windows CI should run tests/probes safely (no interactive powershell config or service creation).
