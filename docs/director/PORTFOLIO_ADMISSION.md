## Admission protocol

For any promotion beyond this table:

1. Record the **exact source repository, commit SHA, file/blob SHA, owner and license**; read the specific source and tests, not just a README.
2. Classify the candidate as unchanged import, adaptation, research-only, historical-only, deferred, or rejected. Explain why a Director-owned interface is preferable to hidden runtime coupling.
3. Specify an observable Director behavior and a standalone test with an independently derived expected result. Preserve inherited source attribution, including earlier HC lineage when applicable.
4. Keep **observation, hypothesis, inference, recommendation, human approval, tool request and verified effect** as distinct records. Multi-agent agreement and role labels cannot mint authority.
5. Independently inspect privacy, credentials, effect targets, network surfaces, crash/replay, licensing and the **absolute $0** incremental-cost boundary.
6. Require exact-head regression and hostile review before accepting implementation code. Treat any future host activation, provider change, credential grant, deployment, or private-data copy as a separate authorized effect.

## First integration target

A standalone, standard-library **recommendation-only decision kernel** should consume explicit mission constraints, evidence references and multiple candidate plans; give a deterministic eligible/rejected/abstain receipt; and execute **no effects**. It can adapt the ideas of Voss evidence classes, DriftGuard's fail-closed admission and Project Runner's bounded work without importing their runtimes, credentials or permissions.

Only after that thin slice is tested should The Director evaluate persistent scheduling, a bus, MCP/A2A adapters or host execution. The existence of an adapter is never approval to call it.
